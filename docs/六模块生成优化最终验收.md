## 2. 四项优化改动

### 2.1 非法场景点 key 局部降级

原逻辑：语义核验返回的 `point_keys` 只要有一条非法，整批分支全部降级 unverified。
修复后：仅降级该条，其余合法分支正常采纳。新增诊断 warning `semantic_point_key_downgraded:<plan_id>`。
位置：`backend/app/services/scenario_coverage.py` 的 `check()`。

### 2.2 场景粒度约束

新增两层约束：
- **提示词层**（`task_pipeline.py` `_COVERAGE_GRANULARITY_POLICY`，仅对 `coverage_generate`/`coverage_supplement` 追加）：一个分支原则上 1 个场景；仅当分支条件含独立业务分支才可拆；禁止把边界取值、品种参数、列举子项拆成独立场景；禁止凑数量。
- **代码硬上限**：`MAX_POINTS_PER_BRANCH = 3`，按模型返回顺序确定性截断，记 `branch_point_cap_truncated:<plan_id>`；必保留分支豁免。

### 2.3 章节范围收紧

原逻辑：普通证据（source_hits/wiki_hits）只判断"是否已选"，不判断章节相关性，导致整本交易规则的条款都进入扩展。
修复后：显式指定 `回归章节` 时，用证据自身结构化元数据（section/section_context/heading/title/path/anchor_clause/canonical_topic）判定相关性；无法判定则保守跳过并记 `out_of_scope_evidence_skipped:<cid>`；未指定章节时保持原行为。必保留项与同章规则正文不受影响。

可追溯：`metadata["scope_filter"]` 记录跳过数量与逐条原因。

### 2.4 required_checks 校验范围

`required_checks` 的 point_key 校验从"当前批 linked"改为"全量 mappings"（`k in mappings` 且 `rid in mappings[k]["required_item_ids"]`）。分支判定 `checks` 的 `linked` 保持本批不变。

**需要说明**：实测证明该改动对真实案例是行为等价（no-op），因为 required 项的绑定点必然在其种子分支所在批次内。保留该改动是作为语义澄清，不作为故障修复计入。真实故障是模型用"普通场景点"去证明 required 项，属于生成器与检查器的关联认知差异，校验器严格拒绝是正确的。
