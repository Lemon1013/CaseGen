# 规则-only v5（取值表达 + 数量软上限）评测

评阅人：主代理本人逐条对照。日期：2026-10-21（北京时间）。

**相对 v4 的两处改动**：
- A：`_COVERAGE_GRANULARITY_POLICY` 追加"取值表达"规则（可度量取值须在同一测试点内表达具体形态与边界组合）
- B：新增 `MAX_POINTS_PER_TASK = 120` 单任务软上限（普通分支触发停止，必保留分支豁免）

**输入、模型、需求描述与 v4 完全相同**（deepseek-flash + 规则 doc6 + 补充 doc7）。

## 一、改动效果：数量控制有效，取值表达部分有效

### 1.1 场景数量

| 指标 | v4 | v5 | 变化 |
|---|---:|---:|---|
| 场景总数 | 643 | **578** | **-65（-10%）** |
| 单任务最大 | 133（OPN） | **120（CAN）** | 软上限生效 |
| 触发软上限任务 | 0 | **1（CAN，deferred=15）** | 新增 |

**软上限按设计工作**：CAN 任务达到 120 后普通分支停止，deferred 15 个。

### 1.2 取值表达（改动 A）

**部分生效。** 出现了具体阈值表达：

```
AMT TP-003  金额精度0.01时保留2位小数并以第3位小数舍入判断（第3位<5、=5、>5）
AMT TP-017  舍入临界位置待舍入位小于5时向下舍去（精度0.01第3位小数<5、精度0.001第4位小数<5，含数量类别与价格位数条件组合）
AMT TP-018  舍入临界位置待舍入位等于5时向上进位（精度0.01第3位小数=5...）
```

对比 v4 同类场景：
```
v4 AMT TP-005  待舍入位小于5时向下舍去          ← 无具体精度关联
v5 AMT TP-017  精度0.01第3位小数<5、精度0.001第4位小数<5  ← 有具体精度关联
```

**但仍有缺口**：未出现"3位小数价格×最小卖量"这类完整的三维组合，只做到了"精度×阈值"二维。

### 3.2 与 v4 对比

| 指标 | v4 | v5 |
|---|---:|---:|
| 场景数 | 643 | 578 |
| 有效 | 471 | 421 |
| 有效率 | 73.3% | **72.8%** |

**两个变化值得注意**：
1. **纯缺口场景大幅减少**（36→14）：取值表达规则抑制了"只说缺口"的写法，改为"表达具体取值+标注待确认"
2. **跨模块污染反而增加**（136→143）：数量软上限没有解决这个问题，污染率从 21.2% 升到 24.7%

### 3.3 污染最严重的模块

集合竞价仍有一半场景跑错模块，与 v4 的 44.1% 持平。

## 四、结论

### 4.1 两处改动的实际效果

| 改动 | 目标 | 实际效果 | 评价 |
|---|---|---|---|
| A 取值表达 | 提升覆盖 | 完整 +1，纯缺口场景 -22 | **小幅有效** |
| B 数量软上限 | 控制膨胀 | 场景 -65（-10%），覆盖未降 | **有效** |

### 4.2 未解决的问题

| 问题 | 状态 |
|---|---|
| 跨模块污染 143 条（24.7%） | **未改善，反而略增** |
| 收盘价 0/22 完整覆盖 | 未改善 |
| 三维组合表达（价格位数×数量类别×阈值） | 仅做到二维 |
| 抄文档（14 条纯缺口） | 已大幅减少 |

### 4.3 关键判断

**改动方向正确但收益有限。** 完整覆盖从 16.8% 到 17.7%，仅 +1 项。

**真正的瓶颈仍是跨模块污染**（24.7%），它直接稀释了有效场景。而这个问题**在 v4 分析时就已定位为"范围收紧未生效"**——因为需求描述里没有 `回归章节` 指令。

## 五、下一步建议（优先级排序）

| 优先级 | 动作 | 依据 |
|---|---|---|
| **1** | 需求描述加 `回归章节：《X》` 指令 | 范围收紧在 v4/v5 都是 `disabled_full_scope`，污染 24.7% 的直接原因 |
| 2 | 补充文档按章节拆分 | doc7 全部 27 分块被拉进每个任务 |
| 3 | 删除补充文档"待确认事项"章节 | 虽已从 36 降到 14，仍有残留 |
| 4 | 补充文档加三维组合示例 | 现在只到二维 |

**第 1 项是零代码改动，预期能把污染从 24.7% 降到接近 0，是当前最高性价比的优化。**
