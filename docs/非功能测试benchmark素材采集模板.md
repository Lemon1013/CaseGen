# 非功能测试 Benchmark 素材采集模板

记录日期：2026-11-18。适用范围：金融交易系统后台的非功能测试方向，用于验证 CaseGen 生成的测试用例质量。本文只定义素材采集与评分口径，不涉及具体业务规则。

## 一、目的与原则

非功能用例的断言必须可量化、可观察、可复现。素材采集围绕这三条原则：

- 可量化：文档中要有具体阈值、时间窗口和口径，避免"高性能""高可用"等形容词。
- 可观察：断言能落到监控指标、日志字段、接口状态或压测报告。
- 可复现：文档版本、系统规格、模型与提示词版本均可固定。

题面只给需求与事实文档，不附带检查点或参考答案，避免"抄答案"式高分。

## 二、按维度收集的文档

| 维度 | 必收文档 | 必须包含的事实 |
|---|---|---|
| performance | NFR/SLO 表、容量规划、压测报告、监控指标字典 | p99 延迟、TPS、峰值时段、资源规格、指标采样口径 |
| recovery | 应急预案、切换演练记录、故障复盘、一致性校验规则 | RTO/RPO、切换条件与耗时、补单/重放规则 |
| security | 权限模型、审计规范、加密脱敏要求、监管条款 | 角色/席位、审计字段、密钥轮换周期、失败锁定阈值 |
| compatibility | 协议/接口规范、版本矩阵、交易日历 | 协议版本、上下游版本、字符集、时区 |
| usability（可选） | 操作手册、错误码表 | 错误提示要求、配置生效方式 |

每份文档入库前标注：版本号、生效日期、适用系统、密级。过期版本单独保留，作为陷阱样本。

补充素材（按需）：

- 系统画像：架构拓扑、部署规格、上下游依赖、交易日关键时点。
- 接口契约：API/报文规范、错误码、状态机、幂等键定义。
- 运维资料：降级开关清单、告警规则、值班手册中的处置步骤。

## 三、单条样本结构

```
ID：NFT-<维度>-<序号>
维度 / 优先级：performance / P0
题面（需求）：目标模块 + 触发场景 + 时间窗口 + 约束 + 验收口径
输入文档：文档名 + 版本
检查点（3–5 条）：
  1. 是否给出量化阈值（如 p99 ≤ 50ms）
  2. 断言是否指向可观察来源（指标名 / 日志字段 / 接口状态）
  3. 是否明确峰值条件与持续时间
陷阱：过期指标、冲突版本、模糊表述
参考用例：TC-xxx（仅评分用，不进模型输入）
```

题面示例：

> 开盘集合竞价期间，撮合服务在峰值 3 万笔/秒申报下，p99 撮合延迟不超过 50ms，网关队列积压不超过 10 秒。

样本字段建议用 JSON 固化，便于批量执行与版本对比：

```json
{
  "id": "NFT-PERF-001",
  "dimension": "performance",
  "priority": "P0",
  "requirement": "开盘集合竞价期间，撮合服务在峰值 3 万笔/秒申报下，p99 撮合延迟不超过 50ms",
  "documents": ["nfr-spec-v3.md", "arch-overview.md", "metrics-dict.md"],
  "checkpoints": [
    "给出 p99 ≤ 50ms 的量化断言",
    "断言基于撮合延迟指标而非端到端耗时",
    "明确峰值申报速率与持续时间"
  ],
  "traps": ["2025 版指标已过期，正确值在 2026 版"],
  "reference_cases": ["TC-NFT-001"]
}
```

## 四、检查点与评分

| 项目 | 分值 | 判定要点 |
|---|---:|---|
| 检查点命中 | 50 | 每条按 0/1/2 计（缺失/部分/完整） |
| 证据与不编造 | 20 | 引用存在、语义一致，未编造阈值或指标名 |
| 可执行可观察 | 20 | 前置、数据、步骤完整，断言能落到指标/日志/接口 |
| 去重与优先级 | 10 | 一例一目标，P0/P1/P2 合理 |

通过条件：总分不低于 80，且无"编造关键指标"严重项。

完整率 = 命中检查点数 / 检查点总数。

存在文档缺口的样本单独标记"证据不足"，不计入生成能力得分，避免把素材缺失算成模型缺陷。

## 五、采集与执行流程

1. 确定维度与样本配额，建议首批 30–50 条，覆盖 performance、recovery、security、compatibility。
2. 收集并脱敏文档：主机名、账户、IP 替换为合成值，保留数值关系。
3. 冻结文档版本与 Wiki 快照，记录模型、温度、提示词版本和检索参数。
4. 编写题面与检查点，检查点只进评分侧。
5. 执行生成，按检查点自动匹配，再人工复核编造、不可执行和重复问题。
6. 归档输入快照、输出结果和评分明细，保证可复现与跨版本对比。

## 六、注意事项

- 不要用真实客户数据、生产密钥或未脱敏配置。
- 不要用真实环境抖动评判模型生成质量，只评断言设计是否可验证。
- 陷阱样本要单独统计，避免拉低正常样本的完整率。
- 评分口径变更时递增模板版本号，并在归档中注明。
