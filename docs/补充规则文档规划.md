# 补充规则文档规划方案

日期：2026-10-21（北京时间）。目的：为规则-only 场景生成补充一份**交易所规则文档未覆盖、但业务上真实存在**的规则说明。

**约束：不参考《竞价基本功能测试.md》清单。**本文的缺口识别完全基于"规则文档缺少什么"，而非"清单要求什么"。为避免无意识照抄清单，本规划只依据规则文档的结构性缺失和通用证券业务常识推导。

## 二、补充文档应覆盖的规则域

按业务逻辑，以下四类规则是规则文档的空白，且是任何证券交易系统都必须定义的。

### 2.1 成交金额计算规则（对应 AMT / ACC）

需要说明：
- 单笔成交金额的计算口径（价格与数量的关系）
- 金额结果的精度要求与舍入方式
- 价格精度的定义（不同品种可能有差异）
- 价格与数量的有效范围
- 多笔成交金额的累加口径（先逐笔计算还是先汇总）

**注意**：具体数值（如"精度0.001"）属于产品配置，补充文档应说明"由产品参数定义"，而不是写死某个数值——否则又变成给答案。

### 2.2 订单类型体系（对应 CAN）

需要说明：
- 系统支持的订单类型分类（如限价单、市价单及其衍生类型）
- 各类订单的适用场景与限制
- 订单生命周期状态的定义

**注意**：具体的类型枚举（本方最优、对手方最优、市转限、市转撤）是**交易所或券商系统的实现约定**，补充文档可以说明"存在按成交价格确定方式细分的市价单类型"，但不逐一列出名称。

### 2.3 撤单规则（对应 CAN）

需要说明：
- 撤单的通用条件（何时允许、何时禁止）
- 不同订单状态下撤单的处理差异原则
- 撤单生效的确认机制
- 撤单与部分成交的关系

### 2.4 金额精度与边界（对应 CLS / ACC）

需要说明：
- 金额计算结果的精度定义方式
- 精度边界（接近进位时的处理）
- 不同品种精度差异的处理原则

## 三、补充文档的写法原则

### 3.1 写"规则结构"而非"测试用例"

✅ 正确写法：
```
单笔成交金额按该笔成交的价格与成交数量计算，计算结果需符合产品定义的金额精度要求。
金额精度的具体位数由产品参数配置，不同品种可能不同。
```

❌ 错误写法（等于给答案）：
```
场景1：3位小数价格，常规买量
场景2：3位小数，第1位小数≥5，最小卖量
```

### 3.2 不写具体数值

- 不写"价格精度 0.001"、"价格范围 0.001~9999.999"
- 写"价格精度由产品参数定义"
- 理由：数值是产品配置，写死就是喂答案

### 3.3 不列枚举清单

- 不写"限价、本方最优、对手方最优、市转限、市转撤"
- 写"按价格确定方式可分为限价类与市价类，市价类下还有细分类型"
- 理由：完整枚举等于把 26 格矩阵直接给模型

### 3.4 明确标注"系统规则"而非"交易所规则"

补充文档应声明：本文描述的是**交易系统实现层面的规则**，不是交易所业务规则。这样模型能区分两类知识来源。

## 四、补充文档结构建议

```markdown
# 证券竞价交易系统补充规则说明

## 说明
本文档描述交易系统在实现交易所规则时所需的系统层规则，
包括成交金额计算、订单类型体系、撤单处理等交易所规则未明确的部分。
本文档不重复交易所规则已有内容。

## 一、成交金额计算
1.1 单笔成交金额的计算口径
1.2 金额精度与舍入方式
1.3 价格精度与有效范围
1.4 多笔成交金额的累加口径

## 二、订单类型体系
2.1 订单类型分类原则
2.2 各类订单的适用场景
2.3 订单生命周期状态

## 三、撤单处理
3.1 撤单的允许条件
3.2 不同状态下的撤单处理原则
3.3 撤单生效机制
3.4 部分成交与撤单的关系

## 四、金额精度与边界处理
4.1 精度定义方式
4.2 精度边界处理原则
4.3 品种差异处理
```

预计篇幅：1500~2500 字。

## 五、预期效果与风险

### 5.1 预期

| 模块 | 当前覆盖 | 补充后预期 |
|---|---:|---|
| AMT | 0/14 | 可能覆盖计算口径类（AMT-001/009/010/013/014），但精度组合类（002~008、011、012）仍需具体数值 |
| ACC | 0/13 | 可能覆盖累加口径类，但尾数类（001~011）仍需具体精度 |
| CAN | 0/26 | 可能覆盖状态维度，但完整矩阵仍需类型枚举 |

**诚实预期**：即使补充文档写好，覆盖率也不会到 100%。因为基准里大量条目依赖**具体数值参数**（精度0.001、尾数X.99），这些属于产品配置，不写进文档模型就推不出，写进去就是喂答案。

### 5.2 风险

1. **又变成变相喂答案**：如果补充文档写得过细，等于把清单规则换个形式给出
2. **补充文档本身是虚构的**：它不是真实存在的交易所文件，是我根据业务常识编写的，用它评测的合法性需要你确认
3. **可能仍不达标**：数值类基准（尾数、精度）本质上无法从任何规则文档推导，必须有产品参数

## 六、需要你确认的三件事

1. **补充文档的定位**：这是"系统实现规范"还是"产品需求说明"？定位决定写法。
2. **是否允许写具体数值**：如"金额精度0.01/0.001"。写了能覆盖尾数类基准，但等于给答案。
3. **是否接受"补充文档是虚构的"**：评测报告需要声明这份文档来源，不能伪装成交易所文件。
