# Wiki 摄入韧性与使用体验优化实施方案

## 1. 背景与问题分级

当前 Wiki 流程把模型输出同时当作“知识提炼结果”和“存储写入指令”。模型需要准确生成 `page_key`、页面类型、创建/更新动作、来源锚点和 Wiki 链接；任一字段不符合数据库或文件约束，整次摄入就可能失败。这会把模型的概率性偏差放大成用户可见故障。

- **P0：摄入可靠性**。重复章节、错误创建/更新动作、非法 key、锚点偏差、单页候选错误不应中断整份文档。
- **P0：知识可追溯性**。原文与原文块必须作为事实层保留，Wiki 仅作为可重建的知识投影。
- **P1：可读性与审核效率**。标题应优先显示中文语义，不应直接展示技术 key；安全审核项应支持批量处理。
- **P2：任务与文档管理**。失败任务可换模型重试，Prompt 应在应用前可编辑，文档应可安全删除。

## 2. 目标架构

采用“事实层—语义层—治理层”三层设计：

1. **事实层**：上传文件、`Document`、`SourceChunk` 是不可由模型改写的原始依据。
2. **语义层**：模型只输出摘要、声明、标题和正文建议，不拥有路径、稳定标识、操作类型和来源关系。
3. **治理层**：服务端归一化模型输出，绑定真实来源窗口，决定 create/update/noop，执行校验、版本记录、审核和索引重建。

核心原则是：严格约束保留在最终仓储边界，但模型输入边界采用宽容解析和确定性修复。普通模型偏差记录为诊断信息；只有原文分析窗口真正降级或页面无法安全落库时，任务才显示警告。

## 3. P0 实施方案

### 3.1 服务端拥有页面身份

- 将分析输出中的 `page_key`、`op`、`page_type` 视为建议。
- 对 key 做安全规范化；无法规范化时按页面类型和原始建议生成稳定哈希 key，禁止路径字符和路径穿越。
- 以数据库现状自动协调动作：create 命中已有页面时转 update，update 未命中时转 create。
- 合并同 key 的重复操作，并按配置限制页面数量；超量部分记录诊断而不抛出整批异常。

### 3.2 来源与正文容错

- 来源只从当前 `SourceChunk` 窗口构造，忽略模型伪造或过期的文档、块和条款标识。
- Step B 使用服务端生成的 `operation_id` 对齐任务；模型只返回标题、正文、领域、别名和标签。
- 模型漏页或写入请求失败时，使用声明、操作原因和原文摘要生成确定性候选。
- 每个候选独立应用；非法链接被降级为普通文本，单页失败转审核项，其他页面继续写入。
- 每次摄入都维护 `source.document.<id>` 来源摘要页，确保结构化页面丢失时仍能从 Wiki 回到原文事实层。

### 3.3 状态与可观测性

- 自动改 key、动作或字段属于 `normalization_notes`，任务保持成功状态。
- 只有分析窗口降级、可能造成事实覆盖不完整时才进入 `success_with_warnings`；单页问题进入审核队列但不污染整份文档的成功状态。
- 步骤日志记录归一化、确定性降级、应用页面、跳过页面和审核项，便于定位具体阶段。

## 4. 体验优化

### 中文标题与类型

写入时从模型标题、操作原因、声明和正文标题中推导中文语义标题；读取旧页面时提供非破坏性的展示回退。前端将 source/rule/entity/scenario/regression/synthesis 显示为来源、规则、实体、场景、回归、综合。

### 批量审核

新增批量审核接口。可写入 create/update 候选自动批准，纯结构提醒自动确认；merge、损坏候选或已被处理的项目逐条跳过并返回原因。每项独立提交，整批只重建一次派生索引。

### 任务恢复

草稿或失败任务允许更新 `model_id`，任务列表和详情页均可“换模型并重试”。模型切换写入任务事件，后续生成沿用现有状态机。

### Prompt 人工确认

应用 Prompt revision 时允许提交编辑后的 `content`。后端仅允许 pending revision，拒绝空白内容，并把最终人工版本同时写入 revision 与任务/全局模板。

### 文档安全删除

删除采用审计墓碑：`Document` 标记为 deleted，历史任务和 Wiki revision 保留；原文件与 `SourceChunk` 删除。共享 Wiki 页面移除该来源并生成新 revision，唯一依赖该文档的页面归档；相关待审核项自动关闭。存在 queued/running 摄入任务时拒绝删除。

## 5. 兼容、发布与验收

- 不迁移或覆盖现有 Markdown；旧英文/技术标题通过读取层兼容。
- 默认 Prompt 升级采用版本和内容哈希，只替换未被用户修改的内置版本。
- 先在测试数据空间验证，再对真实空间重试一份曾失败的长文档；重点观察成功状态、步骤日志、来源链接和待审核数量。
- 验收标准：重复/非法页面建议不导致整批失败；任一已发布规则可追溯到真实文档；自动纠偏不产生红色错误；批量审核部分失败不回滚已成功项；删除后检索不到原文块且历史记录仍可审计。

## 6. 测试矩阵

- 单元：计划 round-trip、非法 key、动作协调、真实锚点绑定、写入身份对齐、中文回退、坏链接降级。
- API：批量审核隔离、失败任务换模型、Prompt 手动编辑、文档删除与活动任务冲突。
- 回归：长文档窗口分析、LLM 502/断连降级、Wiki revision/rollback、空间隔离与混合检索。
- 前端：执行 `npm run build`，并人工验证任务列表、审核页、文档页和 Wiki 分组展示。
